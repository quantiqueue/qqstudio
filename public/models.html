Server

By default qqstudio only answers on this computer. Turn on network access to use it from your phone, tablet or another PC on the same network.
You're connected from another device. These settings can only be changed on the computer running qqstudio.

Sessions

Settings for every session: how much a model may think and write per call, and when long sessions are compacted.

Effort & Token Budgets

What new sessions start at; each session can change both from its effort button. Effort is a hint the model's chat template reads (models that don't support it ignore it). Thinking caps how long the model may think: 1k, 4k, 16k or Unlimited (caps need llama.cpp b9982+).
per model call, on top of the thinking budget
Caps the text and tool-call arguments one call can write. Auto and Unlimited thinking get 4× this. Leave blank for no cap.
Inserted into the model's thinking when the budget runs out, to nudge it to answer.

Session Compaction

%
Sessions will compact when the context window reaches this maximum. The older part is summarized by the model and replaced by the summary in what it is sent; the full history stays in the session. Leave blank to turn it off.

Workspace Memory

tokens per workspace
For workspaces with Memory on (Edit on the workspace). Every session there gets the memory in its instructions. When it passes 80% of this size, it is tidied up: related entries are merged and outdated ones removed.

Privacy

Tokens, API keys, private keys and password-style values that tools return (e.g. from reading a file) are replaced with placeholders like [secret:github-token-1] before they are saved or sent to the model. The model can still pass a placeholder to a tool and the real value is filled in only for that tool. Real values are kept in memory only, until the harness restarts.

Loadouts

An engine, a model and how to run it. Sessions pick a loadout, and it loads when it's used. One loadout runs at a time: loading another unloads it. One model can have several (e.g. a long-context one and a fast one).

Agents

Sub-agents take a separate piece of work from a reply and do it in the background, in their own session with their own context, then report back. They use the session's loadout, effort, thinking, approval mode and tools, but can't ask you questions or start sub-agents of their own. The model gets them through the Agents tool group (＋ menu in a session).
sub-agents at a time, per reply
More can be started at once: the extra ones wait as pending and start as others finish. The model is told this number. Also capped at the engine's parallel slots minus one. With one GPU, sub-agents running side by side share its speed; while the main reply waits, a single sub-agent runs at full speed.
words at most
The sub-agent's final report, which goes back into the main conversation. Both the sub-agent and the model starting it are told this limit; longer reports are shortened.

Tools

Choose what the model may do. "Ask first" shows an Allow / Deny prompt in the chat before the tool runs.
for MCP servers overtokens
A server whose tool definitions are larger than this is listed to the model by name only, and the model asks for a tool's details when it needs them. This saves context and keeps the prompt cache valid when the server is turned on. Leave blank to always send full details.
